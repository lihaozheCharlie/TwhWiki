# 构建：生活经历

本 Skill 是 `wiki/06 现实系统/`，以及 `wiki/07 人物与城市/` 下生活过的城市、组织/项目和出现过的地点的唯一模板负责人。人物证据路由到 `knowledge-engine/skills/build/people/SKILL.md`，不要在这里复制人物模板。

## 先读

- `knowledge-engine/skills/common/filing-rules.md`
- `knowledge-engine/skills/common/quality-gate/SKILL.md`
- 既有目标页及其引用的来源

需要解释现实系统的意义、城市体验、组织功能或地点长期影响时，同时读取 `knowledge-engine/skills/common/reasoning-lenses/SKILL.md`。

## 共享推理视角

- 当前结构、金额、地点、组织关系、时间和可观察状态先按强度 0 中性整理。
- 系统意义、主要张力、城市性格、遗憾与长期影响使用强度 2：运行 `python3 knowledge-engine/skills/common/reasoning-lenses/scripts/list_lenses.py`，选择 1 个主视角，通常最多 1 个辅助视角。
- 家庭、亲密、悲伤和城市生活不能被商业、工程或投资视角商品化；职业、资产和组织页也不能因感受视角而忽略现实约束。
- 领域模板始终优先。人物视角改变解释，不把系统页和城市页写成回信。
- 新人物由共享目录动态发现，本 Skill 不维护人物名单和固定领域映射。

## 现实系统

用于家庭、职业、身体、资产、注意力、表达、居住、时间或风险管理安排。

系统页只应包含有证据支持的以下内容：

- `当前定义`：系统包含什么；
- `当前结构`：锚点、约束、依赖和取舍；
- `当前状态`：可观察状态和证据强度；
- `主要问题与风险`：当前张力和转移成本；
- `操作规则`：决策规则或低风险下一步；
- `关键证据`：精确来源链接。

如果证据没有改变状态、风险、动作或约束，就不要更新系统页。不要把系统页写成泛泛的价值观总结。

解释层可以使一个此前被工具化的生活价值获得独立位置，但操作规则仍需由证据支持，不能从人物原则直接生成。

## 生活过的城市

`wiki/07 人物与城市/生活过的城市/` 只使用以下城市模板：

- `城市定位`：城市在用户生活系统中的作用；
- `初到印象`：抵达、情绪质地和最初的现实问题；
- `生活片段`：有代表性的日常场景；
- `关键经历`：事件、决策、关系或转折；
- `城市性格`：用户对城市的解释，并明确标为解释；
- `遗憾与告别`：未完成事项、成本、遗憾或阶段如何结束；
- `长期影响`：对后来阶段、系统、关系、资产或选择的影响。

城市总览页可以保持导航性质，但必须指向这一标准。

城市性格与长期影响是解释而非事实。主视角可以决定先看感官生活、身份转换、关系网络或现实约束，但必须回到具体城市片段。

## 组织与项目

记录：

- 组织或项目是什么，以及证据边界；
- 它在用户生活或工作系统中的功能；
- 相关人物、事件、决策和城市；
- 它的功能如何随时间变化；
- 代表性来源。

不要仅凭名称出现就推断战略、归属、成败或动机。

## 出现过的城市与地点

一次性出现的地点保留为链接或轻量证据节点。只有地点反复出现、承载人生阶段或现实系统，或为事件/决策提供重要背景时，才创建独立页面。

## 共享实体规则

- 保留别名并避免重复页面。
- 建页前必须通过显著性门槛。
- 解释节点的功能，不要只说它出现在日记里。
- 区分可观察事实、用户解释和模型推断。
- 修改完成后应用 `knowledge-engine/skills/common/quality-gate/SKILL.md`。
