# 构建：状态追踪

当笔记或对话改变当前状态、趋势、风险、习惯、健康、工作状态、家庭状态、表达、注意力或情绪基线时，使用这个 skill。

## 先读

- `knowledge-engine/skills/common/quality-gate/SKILL.md`
- 本文件中的 `state-tracking-builder` 迁移段落。
- `wiki/11 状态追踪/状态追踪总览.md`
- 存在时读取 `wiki/11 状态追踪/值得聊聊.md`。

需要检查状态记录是否只剩问题、行动或效率时，可以读取 `knowledge-engine/skills/common/reasoning-lenses/SKILL.md`，但仅使用强度 1。

## 契约

1. 将证据分类为优化、劣化、稳定或证据不足。
2. 适合时，在来源笔记尾部添加 `## 状态追踪`。
3. 当新证据改变追踪项，或多篇笔记确认同一趋势时，更新 `wiki/11 状态追踪/状态追踪总览.md`。
4. 当已有理解出现值得用户亲自补充的处境、反例、人物、动机或判断时，更新 `wiki/11 状态追踪/值得聊聊.md`；先邀请表达，再帮助理清线索，不把问题写成任务或诊断。
5. 只有来源明确支持，或能从已知事实推出低风险、可逆且标为建议的动作时，才记录下一步最小动作。

## 冷启材料的时间边界

导入的旧日记不能被写成今天仍然成立的状态，但这不等于状态层整体 `no-op`。当冷启材料已经形成阶段性理解，同时留下只有用户能补充的近况、反例、人物、动机或判断时：

- `状态追踪总览`只记录来源时间窗内的状态，明确它不是当前结论；没有合适位置时可以保持不变。
- 创建或更新`值得聊聊.md`，把历史理解写进`当前理解`，把“后来怎样、今天是否仍成立”写进`仍然未知`。
- 问题必须询问真实变化或用户判断，不能暗示旧模式延续至今。
- 只有材料没有具体个人经历或没有可追溯理解时，才将问题池标为 `no-op`，并在矩阵摘要中写明理由。

目标页不存在时，按本 Skill 的字段契约创建最小可用页面，不因知识库刚建立而跳过。

## “值得聊聊”问题池契约

问题池是状态追踪的对话入口，不复制状态面板，也不替用户生成答案。保持 8—20 条 `active` 问题；证据变化后改写、暂停或归档已失去时效的问题。产品可以按 `权重`轮换展示，Wiki 只负责问题的质量与可追溯性。

每个问题使用一个二级标题，并完整保留以下字段：

```markdown
## 主题名

- 问题：一条用户可以直接回应的开放问题
- 当前理解：已有 Wiki 能支持的阶段性理解
- 为什么现在：此刻提出它的证据理由
- 仍然未知：必须由用户补充或纠正的空白
- 观察信号：未来可留意的具体变化（可省略）
- 相关知识：至少一个可追溯的 Wiki 链接
- 状态：active
- 权重：1 到 5
```

生成或维护问题时：

- 优先寻找“系统已经有一点理解，但缺少用户处境与判断”的地方；纯粹没有证据的泛问不进入问题池。
- 问题必须允许用户回答“不是这样”，不能把推断藏进封闭式问法。
- 同一主题可以从人物、动机、反例、选择或意义等不同角度提问，但不能机械换词凑数量。
- 不用“应该、改进、完成、解决”制造待办感；先帮助用户把生活说具体，再组织线索。
- `当前理解`与`为什么现在`必须能回到`相关知识`；`仍然未知`不能伪装成已知事实。

## 护栏

- 不要把状态追踪写成自责清单。
- 不只追踪问题，也要追踪优势是否继续发挥。
- 不做诊断，只描述可观察的状态证据。
- 不把“值得聊聊”写成审问、测评、建议清单或提升效率的任务。
- 优化、劣化、稳定和证据不足必须先中性分类。人物视角只能在分类后检查是否漏掉情感、生活价值、长期承担或现实风险，不能改变事实状态。
- 如需视角审查，运行 `python3 knowledge-engine/skills/common/reasoning-lenses/scripts/list_lenses.py` 动态发现人物；不维护固定名单，不把人物姓名写进状态块。

# 状态追踪构建器（state-tracking-builder）

状态追踪回答的问题是：**这份新材料说明我正在变好、变差、保持稳定，还是证据不足？**

## 先读

- `wiki/11 状态追踪/状态追踪总览.md`
- `wiki/11 状态追踪/日记状态评估模板.md`
- `knowledge-engine/skills/common/quality-gate/SKILL.md`

## 日记尾部格式

当日记包含状态信号时，使用这个区块：

```markdown
## 状态追踪

- 优化：
- 劣化：
- 稳定：
- 证据不足：
- 下一步最小动作：
```

空类别可以省略，但判断必须明确。

## 什么时候更新总览

仅在以下情况更新 `状态追踪总览`：

- 这份来源是强代表性样本；
- 最近三份来源指向同一趋势；
- 需要新增追踪项；
- 新证据推翻或修正了旧判断。

## 质量标准

- 优势和改善与问题同样重要。
- 不要把正常悲伤、休息或责任感病理化。
- 每条 `劣化` 都要说明可控边界；如果没有足够证据支持动作，明确写
  `证据不足` 并省略动作，不得为了填模板而编造。

## 反模式

- 把追踪写成羞耻清单。
- 对纯事件记录强行做状态判断。
- 每篇日记都更新总览。
