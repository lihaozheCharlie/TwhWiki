# 导入后冷启构建

用于 Studio 将一份或一批 `direct` 生活记录首次收进知识库。它仍然遵守影响矩阵和各领域负责 Skill，不要求每个领域都有更新。

## 工作流

1. 从导入清单确定本次批次边界，完整读取每份目标材料，不把同目录旧文件带入本轮。
2. 将材料分类为日记、对话或其他来源；填写完整影响矩阵，并合并跨文件重复证据。
3. 按矩阵更新真正受影响的综合页与来源导航；原始记录正文保持不变。
4. 冷启时额外检查两个产品派生面：
   - 使用 `build-state-tracking` 判断是否应创建或更新`值得聊聊.md`。历史材料不冒充当前状态，但可以形成“当时已知、今天仍未知”的可追溯问题。
   - 使用 `build-companion-reflection` 判断本批是否有一篇值得回应的代表性个人来源；有则标记 `companion=update` 并生成或更新一封回信，不逐文件机械生成。
5. 目标目录或总览尚不存在时，由对应领域 Skill 创建最小可用结构；新知识库不是跳过派生内容的理由。
6. 应用质量门，并在最终报告中分别说明综合理解、值得聊聊、近况回信的 `update` 或带证据理由的 `no-op`。

## 完成条件

- 每个目标文件已被实际读取并纳入同一份矩阵判断。
- 新增判断能回到具体来源，且没有改写原始正文。
- `state` 和 `companion` 不能仅因来源日期较早、页面尚不存在或批次文件较多而 `no-op`。
- 验证失败时明确区分“内容已经写入”和“质量门仍有问题”，不得把已落盘的整批材料当成完全未处理。
