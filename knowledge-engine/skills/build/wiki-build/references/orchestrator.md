# Wiki 构建编排器

用于用户明确要求的宽泛运行，或同时有多种来源发生变化的情况。

1. 使用 `git status --short` 发现候选变化，但不要假设每个未提交文件都属于当前任务。
2. 区分用户既有修改与本次运行获授权的来源。
3. 将每个授权来源分类为日记、对话、非日记来源或生成/导航维护。
4. 填写 `knowledge-engine/skills/build/wiki-build/impact-matrix.md` 的每一行。
5. 只读取标为 `update` 的行所对应的负责 Skill 和参考文件。
6. 对 `link-only` 只做最小的导航或来源链接更新。
7. 对 `defer`，只有本次运行获授权追加维护日志时才记录原因。
8. 应用质量门，并报告跳过或尚未解决的行。

不要把生成索引或验证器通过，当作已经检查语义层的证明。
