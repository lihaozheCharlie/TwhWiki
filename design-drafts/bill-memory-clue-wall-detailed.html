③ 路径一：确认为事实

给几乎不需要讲述的琐碎线索

当线索本身已经足够清楚、置信度高、且没有值得展开的故事时（比如固定通勤咖啡），用户不需要回答任何问题，一次点击直接把「账单事实」转成「已确认的记忆片段」。

  1. 点击「确认为事实」

    卡片原地展开一个确认面板（不跳转、不打开新对话），面板顶部用一句话复述系统要收录的内容，并列出支撑这句话的原始账单证据。

  2. 核对证据摘要

    用户只需要判断这句复述对不对，不需要另外写文字；如果复述有偏差，也可以点击「不对，简单说说」直接降级进入路径二。

  3. 提交确认

    点击「确认收录」后卡片立即变为已确认态，同时右上角弹出一条可撤销的提示条，给一段时间内的「撤销」窗口。

  4. 可随时撤销/重做

    撤销窗口过后，已确认的结果仍非终态——用户可以在卡片墙里随时点回这条线索重新处理，直到最终「构建入 Wiki」之前都可修改。

④ 路径二：简单说说

一次性小问答，不进入多轮追问

当线索有一点值得补充的信息、但还不足以撑起一段完整叙述时，用「预置选项 + 一句话补充」的轻量问答收集，最多允许一次追问（仅当回答模糊到无法收录时），绝不会像深聊一样反复展开。

  1. 点击「简单说说」

    卡片原地展开一个问题，问题由系统针对这条线索的模式生成（比如骑行线索问「这是新习惯还是一直都有？」），并预置 2～4 个最常见答案作为快捷选项。

  2. 选快捷选项，或自己补一句

    用户可以只点一个选项直接提交，也可以在选项下方的一行输入框里补充一句话；两者可以同时使用（选项 + 半句补充）。

  3. 系统判断是否需要追问

    如果选项已经足够清楚，直接进入已简答态；只有当用户选择了「其他」且没有补充说明、导致内容无法收录时，才会追加一次更具体的追问，追问后不再继续深入。

  4. 提交后立即收录

    整个过程都在卡片内完成，不会打开独立对话窗口，提交后卡片立刻切换为已简答态并展示收录的一句话结果。

⑤ 路径三：展开细聊

复用现状的开放式追问对话

只有用户主动判断「这条线索背后有故事」，才会点开细聊——这时才切换到现状已经跑通的深度对话体验，改动范围最小，只是把入口从「系统强制开场」换成「用户主动选择」。

  1. 点击「展开细聊」

    页面从卡片墙过渡到对话面板（原地展开为侧栏，或整屏切换，视线索卡片数量与屏幕宽度而定），卡片墙保留在收起状态，可随时「收起对话」回去。

  2. Agent 用一句话点出联系，抛出第一个开放式问题

    与现状完全一致：不罗列账单明细，先给出一个有温度的观察，再问一个具体但开放的问题。

  3. 多轮追问，直到叙述完整

    用户回答后 Agent 复述要点、追问下一层，反复若干轮，直到这段经历讲清楚为止——这一层逻辑不改动。

  4. 收起对话，返回卡片墙

    用户可以随时点「收起对话」，未讲完也会保存当前进度；卡片状态变为「已深聊」，摘要显示已聊到的要点，之后随时可以点回去继续聊或直接结束。

⑥ 构建入 Wiki 的触发条件

Step 3 · 与现状保持一致的最终确认

「构建这份记录」按钮不要求全部 10 条线索都处理完——用户可以主动跳过不感兴趣的线索；按钮真正的门槛是「每条线索都有一个明确归属（已处理或已跳过），不存在悬而未决的状态」。点击后弹出最终确认，逐条列出将被摄取的内容，账单原始明细依旧只作为参考证据留存。

⑦ 需要提前设计清楚的边界情况

决定这套方案是否站得住的细节
撤销窗口之后怎么办

已确认 ≠ 不可修改

撤销提示条只是即时纠错的快捷通道，过期后不代表锁死——只要还没点「构建入 Wiki」，任何已确认/已简答的卡片都可以重新点开、切换成别的处理方式。

简答与深聊的边界

简答里的一句话补充算不算「细聊」

简答阶段的自由输入框只做「一次性收录」，不会触发多轮追问；如果用户在简答里写的内容明显比预期复杂（比如写了一整段故事），系统应识别并提示「这条更适合展开细聊」，而不是强行按简答逻辑截断。

线索之间的联动

一条线索的回答影响另一条线索

比如用户在「杭州旅程」深聊里提到的朋友，恰好也出现在「单日多笔 5/18」线索里——需要设计一种轻量提示（而非强制关联），让用户知道这两条线索可能相关，但不强迫立刻处理。

长时间搁置

卡片墙不是一次性任务

用户可能处理了 3 条就离开，几天后才回来——需要保留进度、允许随时退出而不丢失已完成的部分，且不能在用户每次打开时都重新提示「还剩 X 条待处理」造成压力感。

落地顺序建议

  1. 先做卡片墙的信息架构 —— 把现有线索列表（Sources.tsx 里已有的候选线索数据）改造成同屏展示，不动对话逻辑。
  2. 再接「确认为事实」 —— 风险最低、收益最直接，能立刻缓解「琐碎线索也要重问答」的问题。
  3. 然后接「简单说说」 —— 需要为每种线索模式（商户重复/单日多笔/跨日期主题等）预先设计对应的预置问题与选项。
  4. 「展开细聊」直接复用现状对话组件 —— 只需改造触发方式（从系统自动开场改为用户主动点击），核心追问逻辑不变。
  5. 最后打通构建入 Wiki 的确认弹层 —— 把「已跳过」也纳入合法终态，避免用户被迫处理不想聊的线索。
