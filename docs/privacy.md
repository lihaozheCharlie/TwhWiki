# 隐私与开源检查清单

个人 Wiki 天生包含高敏感信息。把构建框架开源和把私人知识库公开，是两件完全不同的事。本仓库的样例全部虚构；你自己的仓库默认不应公开。

## 常见泄露面

- 真实姓名、昵称与别名映射。
- 手机号、邮箱、住址、身份证件和精确定位。
- 公司内部项目、未公开组织变化、绩效和薪酬。
- 聊天记录中未同意公开的第三方信息。
- 图片 EXIF、截图、录音、附件文件名。
- 本机绝对路径、用户名、云盘目录和备份位置。
- API key、访问令牌、Cookie、私有仓库地址。
- 已从当前版本删除，但仍存在于 Git 历史的敏感内容。

## 发布前

1. 从一开始就建立新的公开仓库，不要复制私人仓库的 `.git/`。
2. 只复制体系文件；示例使用虚构人物、组织、地点和日期。
3. 删除附件，或逐个检查元数据与版权。
4. 运行 `python3 tools/privacy_scan.py`。
5. 使用 `git diff --cached` 人工阅读即将提交的每一行。
6. 检查 Git 历史，而不只是当前工作树。
7. 让另一位可信任的人做一次独立复核。

## 自定义 denylist

在仓库根目录创建不会被 Git 跟踪的 `.privacy-denylist`，每行放一个不应出现在公开内容里的词，例如真实姓名、内部项目代号或私人域名。扫描器会把它们当作纯文本匹配：

```text
真实姓名
internal-project-x
private.example.com
```

不要提交这个文件；它本身就是敏感信息集合。

## 一旦已经泄露

仅从最新提交删除文件通常不够。应立即撤销暴露的密钥，评估第三方信息影响，清理 Git 历史，并重新扫描所有分支和标签。必要时删除旧仓库并重新发布干净历史。
