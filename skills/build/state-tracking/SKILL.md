# 构建：状态追踪

当笔记或对话改变当前状态、趋势、风险、习惯、健康、工作状态、家庭状态、表达、注意力或情绪基线时，使用这个 skill。

## 先读

- `skills/common/quality-gate/SKILL.md`
- 本文件中的 `state-tracking-builder` 迁移段落。
- `wiki/11 状态追踪/状态追踪总览.md`

需要检查状态记录是否只剩问题、行动或效率时，可以读取 `skills/common/reasoning-lenses/SKILL.md`，但仅使用强度 1。

## 契约

1. 将证据分类为优化、劣化、稳定或证据不足。
2. 适合时，在来源笔记尾部添加 `## 状态追踪`。
3. 当新证据改变追踪项，或多篇笔记确认同一趋势时，更新 `wiki/11 状态追踪/状态追踪总览.md`。
4. 只有来源明确支持，或能从已知事实推出低风险、可逆且标为建议的动作时，才记录下一步最小动作。

## 护栏

- 不要把状态追踪写成自责清单。
- 不只追踪问题，也要追踪优势是否继续发挥。
- 不做诊断，只描述可观察的状态证据。
- 优化、劣化、稳定和证据不足必须先中性分类。人物视角只能在分类后检查是否漏掉情感、生活价值、长期承担或现实风险，不能改变事实状态。
- 如需视角审查，运行 `python3 skills/common/reasoning-lenses/scripts/list_lenses.py` 动态发现人物；不维护固定名单，不把人物姓名写进状态块。

# 状态追踪构建器（state-tracking-builder）

状态追踪回答的问题是：**这份新材料说明我正在变好、变差、保持稳定，还是证据不足？**

## 先读

- `wiki/11 状态追踪/状态追踪总览.md`
- `wiki/11 状态追踪/日记状态评估模板.md`
- `skills/common/quality-gate/SKILL.md`

## 日记尾部格式

当日记包含状态信号时，使用这个区块：

```markdown
## 状态追踪

- 优化：
- 劣化：
- 稳定：
- 证据不足：
- 下一步最小动作：
```

空类别可以省略，但判断必须明确。

## 什么时候更新总览

仅在以下情况更新 `状态追踪总览`：

- 这份来源是强代表性样本；
- 最近三份来源指向同一趋势；
- 需要新增追踪项；
- 新证据推翻或修正了旧判断。

## 质量标准

- 优势和改善与问题同样重要。
- 不要把正常悲伤、休息或责任感病理化。
- 每条 `劣化` 都要说明可控边界；如果没有足够证据支持动作，明确写
  `证据不足` 并省略动作，不得为了填模板而编造。

## 反模式

- 把追踪写成羞耻清单。
- 对纯事件记录强行做状态判断。
- 每篇日记都更新总览。
