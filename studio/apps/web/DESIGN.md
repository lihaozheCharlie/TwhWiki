# Design System: The Way Here

## 当前方向

**Creative North Star:「会继续生长的个人档案」**

**Product Mind:「有什么，都可以聊聊」**

界面像一位认识很久、也愿意继续听下去的朋友所保留的个人档案：雾白画布、纸面内容、深蓝灰文字、青绿色路径标记。标题使用中文衬线字传递时间感，正文保持现代无衬线的可读性。结构主要依靠留白、细线和排版形成，不依赖大阴影、渐变和高饱和色块。朋友感来自记得上下文、承认未知和邀请纠正，不来自头像、拟人插画或模拟情绪。

本规范来自 2026-08 最新 UX 方案。首页、原始知识、知识总览与所有知识浏览页遵守同一套鼠尾草档案主题。`archive-foundation.css` 只提供这套主题的共享结构，`archive-theme.css` 负责 token 与视觉规则；页面级样式不得另起品牌色、玻璃材质或大圆角系统。

## 设计原则

- **先读后操作。** 首屏先说明当前页面是什么，再给出少量明确动作。
- **证据是一等信息。** 数量、日期、来源和关联紧邻内容出现，用户能随时回到原文。
- **扁平默认。** 普通集合用边界和相邻色面分层；阴影仅用于真正覆盖页面的浮层。
- **低圆角。** 完整内容面使用 8px，表单和按钮使用 4–5px；胶囊仅用于标签或单一筛选状态。
- **强调色克制。** 青绿色只表达路径、当前状态、焦点和可继续前行的动作；暖金色只表达需要留意的局部状态。
- **内容真实。** 设计稿示例必须接入当前知识库数据，不把示例文案硬编码成产品事实。
- **先问一个具体问题。** 首页和“值得聊聊”不能把空白输入框当作主角，也不能一次铺开问题清单。系统先从可追溯的已有理解与未知中选出一个用户可能关心的问题，直接问；用户可以换一个，也可以主动聊别的。
- **记录入口始终可见。** 首页必须清楚提供“带进生活记录”的入口，并明确支持日记、笔记、AI 对话、微信记录和消费账单。记录不是冷冰冰的导入任务，而是让后续问题更具体、理解更有来路的另一种起点。
- **一句话只做一件事。** 标题能说明的内容不再用副标题重复，具体问题前不添加“今天我想问你”一类气氛标签，相邻区块不重复同一个动作。两段解释同一件事的小字必须合并或删除。
- **亲近但不越界。** 可以使用“我会记得 / 一起聊聊 / 还不懂你”，同时持续显示证据、未知、实际改动和原始笔记保护，不能用朋友口吻掩盖 Agent 的能力边界。
- **只交付桌面端。** 当前设计与验收范围是桌面 Web；不得在普通功能开发中顺带增加手机、平板、触控或窄屏适配，也不为这些设备制作设计稿或截图。只有产品范围明确调整后才重新设计这些体验。

## 色彩

- `#f4f7f6` 雾白画布：应用背景。
- `#fbfcfc` 档案纸面：内容卡片、阅读区、输入面。
- `#263440` 深蓝灰墨色：标题、正文、主要按钮。
- `#5f706f` 次级灰绿：说明、日期、数量与辅助信息；在纸面与雾白底上保持正文可读对比度。
- `#d9e1df` 档案边界：结构分隔线。
- `#578a83` 路径青绿：活动项、当前节点、链接与焦点。
- `#b9874c` 提醒金：需要停下确认的短标签或状态点。

页面层级优先使用纸面、雾白和细边界。路径青绿和提醒金不得铺满大面积页面容器。

## 字体

展示标题使用 `Georgia / Songti SC / STSong / Source Han Serif SC` 回退栈，字重 500。正文、导航和控件使用本地 `Noto Sans SC Variable`。

- 首页主标题：48–76px，行高 1.14，最多约 12 个汉字宽。
- 页面标题：38–62px，行高 1.08。
- 区块标题：24–40px。
- 正文：13–16px，行高 1.7–1.9。
- 数据标签：10–12px，可使用等宽字体与轻微字距。

衬线字用于标题、引用和关键阅读节点，不用于表单、长段正文或密集文件列表。

## 布局

桌面端全局导航高 64px，知识局部导航高 50px，内容宽度上限 1600px，左右至少保留 32px。一级导航依次为“此刻 / 值得聊聊 / 生活记录 / 已有理解”。首页固定以“有什么，都可以聊聊”作为产品论点，并紧接着直接提出一个可回答的具体问题；不得以空白对话框要求用户自己发明开场，也不得用三卡、九宫格或长列表同时推销多个问题。问题每天稳定轮换，允许“换一个”，完整问题库只通过小型次级入口进入。

首页在首个问题之后必须继续露出一次“带进生活记录”的独立入口，用“日记、对话和账单”说明范围，并以一句话交代它会让后续问题更具体；同一屏内不再出现第二个同名动作。其后仅用单行紧凑索引透出已经形成的理解。首页不得展示“现在的你”、阶段摘要、最近材料、本人引用、知识摘要、补充动作或完整人生轨迹；这些内容属于各自的二级页面。问题不是待办事项；主问题直接以问句出现，不加拟人化提问标签，也不在首屏解释提问理由。

知识总览先显示总量与来源，再进入理解自己、人生轨迹和人与世界三个空间。人生轨迹页面直接以时间线呈现，不设置额外视角切换；近况回信作为独立二级入口，紧邻人生轨迹。原始知识使用文件夹、文件列表、正文阅读三栏结构；目录与文件列表在桌面端保持粘性，页面拥有唯一纵向滚动。

消费账单从生活记录的统一入口带进来。选择文件时强调它会被整理成“消费旅程”，而非生成财务报表；完成后用一条有真实时间顺序的线索带呈现地点、重复消费和跨类型事件，唯一主要动作是“聊聊这段旅程”。每段旅程只延续一段对话：已有对话时，入口直接打开完整历史并从末尾继续，不另建话题。线索带只展示聚类依据与候选关系，不把消费推断写成用户已经确认的经历。

当前桌面设计基线为 1280–1600px 宽的鼠标与键盘环境。新页面和新组件只需维护桌面信息密度与操作路径；不要新增移动端断点、折叠导航、底部抽屉、触控尺寸或单栏重排。仓库中既有的窄屏样式属于历史兼容代码，不构成后续功能的交付要求，也不应在无关任务中扩展。

## 组件约定

### 导航

活动项用字重与底部青绿色细线表达，不使用大面积选中胶囊。个人空间切换、搜索和内容导航各自独立。品牌中的 `Here` 使用路径青绿，作为跨页面稳定签名。

### 按钮

主要动作使用深蓝灰底、白字、5px 圆角；页面内最多突出一个主要动作。次要动作使用透明底或细边界。键盘焦点统一使用半透明青绿色 3px 外轮廓。

### 卡片与列表

首页入口和知识空间使用 8px 纸面卡片；连续材料、人物和知识页面优先使用共享边界的行列表。Hover 只改变纸面色或边界色，不使用明显位移和强阴影。

### 值得聊聊

“值得聊聊”页一次只把一个问题放在视觉中心，左侧只保留“值得聊聊”页名，不再解释选题机制。问题本身必须是完整、具体、可以直接回答的问句。其下用两个安静区域说明“我现在的理解”和“我还不知道”，主要动作是“说说看”，次要动作是“换一个问题”和“看看依据”。其余问题默认隐藏，只保留一条弱化的“看看其他 N 个问题”入口；只有用户主动展开后才能出现完整列表。无论数据是否充足，都不得用空文本框代替提问，空状态应退回一个关于最近具体小事的问题。

### 阅读与编辑

长文正文在独立阅读页保持舒适行宽，在三栏编辑工作区内自适应占满正文列。标题区、属性区、正文和大纲依次分层；双击进入编辑、自动保存和证据关联能力继续复用同一实现。页面不能出现正文内滚动与浏览器滚动并存的双重视口。

近况回信只有一个版本时保持纯阅读面，不显示版本控件；存在两个及以上版本时，在正文上方显示版本切换器，并默认打开最新完成版本。版本名称使用“雅尼视角回信”一类可读来源标签，同时标明日期与最新版本、历史版本或最初版本；原始回信始终保留。版本区继续使用纸面与雾白的扁平色层、细分隔线、克制圆角和衬线阅读层级；生成版本在正文前显示紧凑的来源元数据行，并提供“查看生成对话”动作。

### 上下文 Agent 抽屉

Agent 只使用一个右下角深蓝灰浮动入口和覆盖页面的右侧抽屉，与知识导航分开，不再设计独立工作台。日常入口称“找我聊聊”，抽屉顶部持续显示当前个人空间与页面标题，内部在新话题、“我们聊过的事”和完整线程详情间切换；普通对话由 Agent 判断只回答还是沉淀，实际变更和验证结果必须清楚展示。人物视角重读也在此抽屉内创建；开始前显示将保留的版本标签，并明确原始回信仍可切换查看，完成后同时在对话详情中确认已保留为最新版本。关闭后将键盘焦点还给实际触发抽屉的控件；若该控件已移除，再回退到固定浮动入口。

## 动效与可访问性

仅在首页首屏使用一次轻微上浮淡入。Hover 和焦点转换控制在 180–220ms；尊重 `prefers-reduced-motion`。所有选中状态同时使用形状、文字或位置表达，不能只依赖颜色。

## 视觉验收

- 1280–1600px 桌面宽度无横向溢出，主要操作无需触控或窄屏专用交互。
- 首页、原始知识、知识总览和至少一个知识子页需要截图检查。
- 品牌、导航、标题、边界和操作色在所有页面一致；不得重新引入 Apple 蓝、装饰性玻璃模糊或另一套页面 token。
- 运行 `design:check`、类型检查、前端测试与生产构建。
