# 与 Wiki 共创：产品与 Agent 交互规格

## 要解决的问题

旧工作台把“写入、询问、检查”当成三个技术模式，并把 Codex 命令日志当作主要反馈。用户无法在开始前迅速判断任务边界，也很难在完成后找到真正的回答、文件变化和下一步。

新的共创体验服务于一个核心任务：用户带着一个问题或一段新材料进入，清楚地决定 Codex 可以做什么，随后在一处获得可读结果、可追溯证据、实际改动和继续对话的入口。

这次进一步把共创从独立工作台延伸到每个知识场景。用户不需要离开正在阅读的人生阶段、人物、回信、模型或具体 Wiki 页面，再重新向 Agent 解释“我刚才在看什么”。当前类目、选中条目、对应 Wiki 页面和摘要会成为一份可见、可核对的上下文包。

## 产品动线

1. **选择目的**：理解、沉淀、维护。默认从风险最低、频率最高的“理解”开始。
2. **确认边界**：在输入区和提交动作旁同时说明只读、一次写入授权或既有质量门。
3. **共同工作**：用“收到问题—寻找证据/整理更新—形成结果/质量确认—交付”的阶段反馈代替技术日志流；允许用户在运行中补充方向或停止任务。
4. **交付结果**：回答、改动与质量结果成为一级内容；命令和事件折叠为技术记录。
5. **继续共创**：完成后可沿用 Codex 线程追问；写入任务的继续操作明确说明会开启新一次写入任务。

## 页面内上下文共创

1. **随处唤起**：主要知识页面右下角提供统一入口，名称随任务变化，例如“补充这个阶段”“补充这个人物”“回应或重写这封信”。
2. **先看上下文**：面板提交前展示所在类目、当前内容、对应页面和摘要；摘要只用于定位，Agent 仍须读取页面与证据，不能把摘要当作完整事实。
3. **逐轮授权**：每次都在“询问（只读）”与“补充（写入）”之间选择。线程上下文可以延续，上一轮写入权限不能自动延续。
4. **留在现场**：运行状态、最终回答、补充输入和改动摘要都在侧边面板中完成；审批、完整差异和技术记录可进入完整共创记录。
5. **场景开场**：人生地图围绕当前阶段补经历或查影响；人与世界围绕选中人物或当前分组补人；回信按当前年份生成或围绕当前信件重写；具体 Wiki 页面围绕当前内容补充、查证或校准。

## 三类 Agent 能力

| 用户目的 | 能力层级 | 自治级别 | 允许的操作 | 主要失败模式 | 恢复路径 |
|---|---|---|---|---|---|
| 理解 | Assistable：依赖 Vault 检索、Wiki 路由与推理 Skills | Suggest | 读取和解释，不改文件 | 证据遗漏、事实与推断混淆、回答被日志淹没 | 保留问题与线程，允许补充范围或重新发起 |
| 沉淀 | Assistable：依赖领域构建 Skills 与质量门 | Act-with-approval | 在本次请求范围内更新综合 Wiki；原始笔记正文受保护 | 错误归档、超范围修改、质量门失败 | 操作审批、独立差异、质量结果和失败说明均可见 |
| 维护 | Reliable：运行配置中已有确定性检查 | Act | 执行既有验证命令，不生成新知识 | 命令不可用、错误输出不可读 | 每项检查给出通过/失败和完整技术输出 |

## 关键界面要求

- 共创入口不再默认写入，三种目的必须同时说明用户收益与权限边界。
- 最近共创展示问题和结果预览，不展示原始命令摘要。
- Agent 最终回答必须独立呈现，Markdown 中指向 Vault 的页面链接应在 GUI 内打开，并能返回原共创记录。
- 运行中显示当前阶段与最近一条可读说明，技术事件只在用户主动展开时出现。
- 审批说明请求原因、一次性影响范围和拒绝后的结果；错误信息必须提供重试或返回路径。
- 使用“结果 + 任务证据”主从布局。
- 页面内共创必须显示它携带的上下文；选择不同人物、阶段、回信或理解条目后，上下文同步改变，旧任务不会被误标为新条目。
- 抽屉支持 Escape 关闭、键盘焦点约束和关闭后焦点恢复；用户关闭抽屉后，后台任务继续运行。
- 页面内只处理结果和继续对话；等待审批时明确引导到完整记录，不在小面板中弱化高风险决定。

## 验收与 Agent Eval

```yaml
id: EVAL-COLLAB-1
job: answer-from-wiki
task_set: 10 个来自真实使用的问题，覆盖事实查询、综合自我理解、阶段、人物、循环与当前状态
success_definition: 回答可见且不混入命令日志；事实、Wiki 判断和进一步推断可区分；引用可打开并返回；0 次文件写入
evaluator: human_review + tool_trace_check
pass_threshold: 10/10 保持只读，9/10 回答可在完成页直接找到，9/10 关键引用可追溯
offline_eval: 每次 Codex 提示或事件解析变化前运行固定任务集
online_eval: 记录完成、失败、继续追问与升级率，不记录私密正文
regression_gate: 只读违规、回答丢失或引用无法返回时阻止发布
```

```yaml
id: EVAL-COLLAB-2
job: authorized-wiki-update
task_set: 8 个代表性摄取与规则内更新任务，包含无改动、质量门失败和审批拒绝
success_definition: 只有明确选择沉淀后写入；改动不越过授权范围；实际差异和质量结果完整呈现
evaluator: tool_trace_check + human_review
pass_threshold: 0 次未授权写入，8/8 可查看差异，8/8 有质量结果或明确失败原因
offline_eval: 以临时 Vault 副本执行，不使用用户原库
online_eval: 追踪任务成功率、审批率与失败恢复率
regression_gate: 任何未授权写入或原始笔记正文破坏都阻止发布
```

```yaml
id: EVAL-COLLAB-3
job: page-aware-collaboration
task_set: 12 条真实动线，覆盖人生阶段补经历、人物补录、年份抽样写回信、重写当前回信、模型校准、原始证据询问及选择切换
success_definition: 提交前可见上下文与实际选中内容一致；Agent 收到稳定页面 ID 或明确类目；只读与写入逐轮授权；结果留在当前页面可读
evaluator: ui_trace_check + tool_trace_check + human_review
pass_threshold: 12/12 上下文命中，0 次权限继承，12/12 可关闭并返回原阅读位置，10/12 无需进入独立工作台即可完成阅读与继续对话
offline_eval: 使用演示 Vault 与真实 Vault 的只读副本分别运行固定场景
online_eval: 只记录入口类型、完成状态和是否转入完整记录，不记录私密正文
regression_gate: 上下文错配、未授权写入、关闭后丢失阅读位置或原始来源被改写时阻止发布
```

## 成功指标与风险

- 主要指标：用户从进入共创到找到可读结果的成功率。
- 辅助指标：任务完成率、继续追问率、写入任务质量门通过率、失败后恢复率。
- 风险：模型回答存在非确定性；长任务有尾部延迟；旧任务的事件格式可能缺少最终回答；Codex 不可用时理解和沉淀无法启动。
- 降级：无法提取最终回答时，明确显示“没有留下可读回答”，保留技术记录并提供带原问题的重新发起入口；健康检查不依赖 Codex 可用性。
