# 照片记忆冷启 · 第一版

## 目标与界面范围

从几张照片开始，先看得见的线索，再由用户认人、讲述和纠正，最后将确认过的记忆收进已有理解。照片不是自动生成「人生事实」的依据。

本功能是现有生活记录流程的局部扩展，采用 Operate 模式，以用户照片为主要内容。沿用档案纸面、既有字体与颜色变量、细边界和克制操作，不另建媒体应用或全局设计系统。交付范围为 1280–1600px 桌面 Web；不包含移动端设计。

入口在「带一段记录进来」中，新增第四类「照片与影像」，保留「选类型与材料 → 确认位置」两步导入。记忆工作区依次呈现标题与状态、步骤、看图操作、缩略图带、照片与线索双栏，以及讲述与确认区。人物影像继续使用既有关系列表、图谱和详情页；聊天继续进入共享上下文 Agent 抽屉。

## 使用流程

1. **选好照片。** 添加照片并为记忆命名，确认来源位置。每批 1–10 张 JPG、PNG 或 WebP，单张可选择最多 100 MB；超过 20 MB 时在本地后台逐张压缩为最长边 2560px 的 JPG，压缩后合计最多 100 MB；不接收动画或 HEIC，HEIC 请先导出为 JPG。导入保存原文件或大图的压缩副本，不改动电脑上的原文件，不自动调用模型。
2. **看线索、认人物。** 导入后默认在后台逐张检测并圈选人脸，检测期间仍可切换照片；可调整或移除检测框，不再提供手动添加。多人用标签切换，一次编辑一人；也可点击照片上的框切换对应人物。不必标出每个人，没有人脸也能继续讲述。已有的人物通过搜索明确关联；新人物由用户填写称呼。确认标注后默认使用裁剪头像。切换照片时分别暂存未确认标注，不要求先保存。
3. **讲述与确认。** 可选择让 AI 看图，再从一个具体问题开始聊；也可跳过模型，直接填写故事。AI 候选线索、用户指定身份、用户确认讲述分别展示。对话用于补全记忆报告，不直接构建 Wiki；核对后点击「确认这份讲述」。
4. **收进理解。** 点击独立的「构建这段记忆」，只摄取确认稿与用户指定的人物。成功完成构建及质量门后，发布人物影像关联。之后继续对话产生新草稿，须重新确认再构建。

## 保存与隐私边界

- **本地检测不等于身份识别。** 浏览器使用随应用分发的 MediaPipe WASM 与 BlazeFace 模型，仅产生候选人脸框，不访问 CDN；不进行人脸身份匹配、跨照片聚类或 embedding。服务端使用 Sharp 从转正副本裁剪头像。
- **点击看图使用当前模型。** 无需额外勾选，点击看图后分析副本会发送给 AI 设置中当前选中的模型服务；原图不会作为分析附件。使用既有 Codex 或用户配置的模型路径，先检查视觉输入能力，不支持时明确提示，不自动切换供应商。外部服务如何处理数据仍取决于其政策。
- **对话也有发送边界。** 丰富故事时发送候选线索、用户指定的称呼和讲述上下文，不重新发送图片；不能把「图片本地检测」理解为「整个对话离线」。
- **草稿不是 Wiki。** 未确认的编辑按知识库与照片批次暂存在本机浏览器。离开、刷新后需明确恢复或丢弃，若服务端版本已变化则提示核对；不自动确认或构建。浏览器存储失败会提示，并在关闭窗口前警告。
- **来源可回看。** 工作区提供「保存原图」。模型线索与未确认草稿保留在隐藏元数据中，确认后的讲述才进入可摄取的来源报告；构建不改写原始照片。

## 人物影像与第一版限制

已有角色只能通过用户选择的页面 ID 绑定，不能根据同名自动合并。新称呼仅在本次成功构建实际新增的人物页中唯一匹配时绑定；没有唯一结果就不发布该关联。头像和照片证据进入关系列表、图谱及人物详情，照片可回到来源报告。移除人物标注后停止提供该关联头像。

删除普通来源报告后，相关影像不再出现在人物视图，但隐藏来源目录中的原图仍然保留。第一版没有整批照片管理或删除界面；删除报告不等于删除照片。当前也不支持视频、自动识人或自动关系推断。

## 验证记录

首版交付检查：类型检查、169 项测试与生产构建通过；实际浏览器中验证了本地检测返回 3 张候选人脸、人物与讲述保存、刷新及导航后的草稿恢复，以及人物列表、图谱和详情影像展示。首轮审查发现的草稿保留与人物图库内边距问题已修复。

本轮没有发起真实云端模型调用。图片附件、结构化输出、确认和构建链路由替身运行时测试覆盖，不代表已验证具体外部模型的视觉质量或数据处理政策。

实现边界与持久化协议参见 `ARCHITECTURE.md` 的「照片记忆冷启」一节。本简报只记录该功能的局部选择，不更新既有 `PRODUCT.md`、`DESIGN.md` 或设计系统 sidecar。
